DATABASE REFERENCE — mysql · team2

데이터 딕셔너리

AWS RDS team2 스키마를 information_schema로 직접 조회해 생성한 현재 시점 기준 문서입니다. 마이그레이션 SQL 파일이나 models.py 주석이 아니라 실 DB 상태를 그대로 반영합니다.

⚠ 문서와 실제 DB가 어긋나 있던 지점
  • migration_trip_interest_use_ctg.sql 파일 주석은 "아직 DB에 적용하지 않았습니다"라고 되어 있지만, 실제 DB에는 이미 적용되어 있습니다 — trip_interest.interest_no 컬럼과 interest 테이블이 모두 사라진 상태이며, trip_interest.ctg_no만 남아 있습니다.
  • migration_visit_feedback.sql도 동일하게 "미적용"으로 적혀 있지만, visit_feedback.reaction_no 컬럼은 이미 제거되어 (visit_feedback_no, trip_route_event_no, created_at) 3컬럼만 남아 있습니다.
  • 즉 두 마이그레이션 파일의 "실행 전 확인 요청" 경고는 더 이상 유효하지 않습니다 — 재실행하면 이미 없는 컬럼/테이블을 지우려다 에러가 납니다.
  • accom.accom_lat/accom_lon은 DECIMAL(11,8)이 최종 스펙입니다 — 이 문서에 한동안 남아있던 DECIMAL(10,8) 표기는 stale이었고, 실DB 재조회로 정정했습니다.
  • (2026-09-10 재확인) 스키마·테이블 구성 자체는 지난 스냅샷과 동일(32개 테이블, 변경 없음) — AL-02 챗봇 쪽 작업(지시어 재작성, 도구 확장 등)은 전부 애플리케이션 로직이라 DB 스키마에 영향 없음. 아래는 행 수만 실 사용량 반영해 갱신.
team2 · MySQL(RDS, ap-northeast-2) · 기준 실 스키마 조회 결과 · 32개 테이블
